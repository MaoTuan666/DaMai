### 设备主流程

以下步骤已经在 API 35 模拟器实际执行：

1. 安装 `app-debug.apk`，系统返回 `Success`。
2. 冷启动 `MainActivity`，前台窗口和 resumed activity 均为配置页，未出现崩溃。
3. 点击无障碍入口，系统打开
   `Settings$AccessibilitySettingsActivity`。
4. 请求通知权限，系统显示运行时权限对话框；允许后配置页显示“运行通知：已允许”。
5. 开启 `TicketAccessibilityService` 后，系统 `dumpsys accessibility` 同时显示
   enabled 和 bound，配置页显示“无障碍服务：已开启”。
6. 填写目标并开始，配置页移到后台；应用未主动打开售票软件。
7. `TaskForegroundService` 进入 foreground 状态，通知 ID 1001 为常驻通知，
   并带有“停止”动作。
8. 左上角出现等待状态、停止按钮和脱敏日志；日志窗口不获取触摸。
9. 点击悬浮“停止”后，前台服务、通知和悬浮窗口全部消失。
10. Room 中 `ticket_task.state` 为 `STOPPED`，价格 `580` 元保存为 `58000` 分；
    `run_log` 依次记录 `TASK_ARMED`、`ENGINE_READY`、`TASK_STOPPED`，
    停止原因为 `USER_REQUESTED`。

### APK 签名状态

- `app-debug.apk`：Android Debug 证书，APK Signature Scheme v2 验证通过，可安装。
- `app-release-unsigned.apk`：R8/资源收缩已完成，未配置正式密钥时保持未签名。
- `app-release-local-test.apk`：仅用于设备验证，使用 Android Debug 测试证书，
  不得作为应用商店或正式分发签名。

正式 Release 需要在仓库根目录提供不纳入版本控制的 `keystore.properties`
和对应密钥。构建脚本会拒绝字段不完整或密钥文件不存在的配置。

### 尚需外部实物条件的验收

本轮没有连接实体 Android 设备，也没有安装并登录真实大麦客户端，因此未记录
“已验证的大麦客户端版本”，也没有在真实页面上触发购票动作。正式发布前必须在
授权测试账号和非生产订单场景中执行技术方案 11.2 的真机矩阵；验证码、风控、
收银台和未知弹窗只验证安全决策，不应在自动化测试中绕过。
