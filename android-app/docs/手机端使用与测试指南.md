# Android 购票辅助手机端使用与测试指南

## 1. 文档目的

本文用于在真实 Android 手机上安装、使用和验收 `购票辅助 0.1.0`。

测试范围包括：

1. APK 安装和启动。
2. 无障碍与通知权限。
3. 任务配置、前台服务和左上角悬浮控制。
4. 大麦三种运行模式。
5. 页面不一致、验证页面、未知弹窗和收银台等安全边界。
6. 测试结果、截图和日志记录。

付款始终由测试人员手动完成。应用不得绕过验证码、登录、风控、设备校验或平台
限制。

## 2. 测试准备

### 2.1 手机要求

- Android 8.0（API 26）或更高版本。
- 已安装来自可信官方渠道的大麦 Android 客户端。
- 测试人员拥有可以合法使用的大麦测试账号。
- 手机可以接收持续运行通知。
- 测试期间应确保随时能使用悬浮“停止”按钮或通知中的“停止”入口。

记录以下实际信息：

```text

Android 版本：
大麦版本：
购票辅助 APK：
测试日期：
测试人员：
```


### 2.3 测试安全要求

- 确认悬浮“停止”按钮可见且可用后，再开始真实流程测试。
- 使用非关键场次或明确允许测试的订单场景。
- 不在无法承担订单结果的项目上测试自动提交。
- 不在文档、截图或日志中记录账号密码、身份证号、手机号、银行卡、订单号和支付

## 3. 将 APK 安装到手机

可以选择文件安装或 ADB 安装。

### 3.1 文件安装

1. 通过 USB 文件传输或其他可信文件传输方式，把
   `app-release-local-test.apk` 复制到手机。
2. 在手机文件管理器中点击 APK。
3. 如果系统要求授权“安装未知应用”，只为当前使用的文件管理器开启该权限。
4. 完成安装后关闭不再需要的“安装未知应用”权限。
5. 在应用列表中找到“购票辅助”。

通过标准：

- 系统能够解析并安装 APK。
- 应用名称显示为“购票辅助”。
- 点击图标后显示“购票任务配置”页面。

### 3.2 ADB 安装

在手机中打开开发者选项和 USB 调试，使用 USB 连接当前电脑。手机弹出调试授权时，
核对电脑后允许本次连接。

确认设备：

```bash
/tmp/ticket-assistant-sdk.w4lEPf/platform-tools/adb devices -l
```

设备状态必须是 `device`，不能是 `unauthorized` 或 `offline`。

安装：

```bash
/tmp/ticket-assistant-sdk.w4lEPf/platform-tools/adb install -r \
/Users/armo/aiCode/DaMai/android-app/app/build/outputs/apk/release/app-release-local-test.apk
```

通过标准：

```text
Success
```

启动：

```bash
/tmp/ticket-assistant-sdk.w4lEPf/platform-tools/adb shell am start \
-n com.ticketassistant.android/.MainActivity
```

## 4. 首次使用设置

### 4.1 开启无障碍服务

1. 打开“购票辅助”。
2. 点击“前往系统设置开启”。
3. 在系统无障碍服务列表中找到“购票辅助页面识别”。
4. 打开该服务并确认 Android 系统提示。
5. 返回“购票辅助”。

通过标准：

- 配置页显示“无障碍服务 · 已开启”。
- 无障碍服务名称为“购票辅助页面识别”。
- 应用没有要求单独的普通悬浮窗权限。

应用更新或重新安装后，需要重新检查页面显示的实际授权状态。

### 4.2 允许运行通知

1. 点击“允许运行通知”。
2. 在系统权限对话框中选择“允许”。

通过标准：配置页显示“运行通知 · 已开启”。

通知用于持续显示任务状态和“停止”入口。通知未允许时，应用不得进入运行状态。

## 5. 任务字段说明

| 字段 | 填写要求 |
| --- | --- |
| 运行模式 | 根据第 7 节选择“只抢票”“只抢回流”或“抢票后接回流” |
| 演出日期 | 用日期选择器选择，保存为 `YYYY-MM-DD`；中文月日可不补零，无年份数字月日必须是双位 `MM-DD`、`MM/DD` 或 `MM.DD`，星期和时间不参与匹配 |
| 票档价格 | 只填数字，单位为元，例如 `580` |

测试前仍需在大麦中完成场次、票档、数量和实名观演人设置。购票辅助不会读取或保存实名资料。
任务没有提交次数或运行时长上限，会持续运行到付款页、用户停止或安全暂停。

## 6. 手机基础功能测试

### TC-P01：应用启动

操作：

1. 从手机桌面打开“购票辅助”。
2. 上下滚动配置页。

预期结果：

- 页面正常显示，没有闪退。
- 能看到平台说明、手动付款边界、任务字段、安全上限和权限状态。
- 页面可以滚动到“保存配置并显示悬浮窗”。

### TC-P02：配置校验

分别使用以下无效配置点击“保存配置并显示悬浮窗”：

- 未选择演出日期。
- 价格为空或为 `0`。

预期结果：

- 对应字段显示明确错误。
- 不启动任务。
- 不出现运行通知和悬浮控件。

### TC-P03：权限校验

操作：

1. 在系统设置中关闭购票辅助无障碍服务。
2. 返回应用并填写合法配置。

预期结果：

- 页面显示“无障碍服务 · 待开启”。
- 应用不启动任务。

撤销通知权限后重复测试：

- 页面显示“运行通知 · 待开启”。
- 应用不启动任务。

### TC-P04：开始任务

前置条件：

- 无障碍服务已开启。
- 通知已允许。
- 配置全部合法。
- 大麦尚未由本应用自动打开。

操作：

1. 点击“保存配置并显示悬浮窗”。
2. 手动打开目标大麦页面。
3. 点击悬浮窗中的“开始”。

预期结果：

- 配置页移动到后台。
- 购票辅助不会自动打开大麦。
- 手机左上角先出现可点击的“开始”和“停止”按钮。
- 通知栏出现“购票辅助正在运行”。
- 点击悬浮“开始”前不识别页面；点击后才显示“正在识别当前页面”。
- 页面未知、目标不匹配或不是合法起始页时不执行点击，并显示对应的脱敏等待原因。
- 同类等待原因 15 秒内最多记录一次；等待原因变化时也至少间隔 2 秒。

补充覆盖以下起始页识别场景：

| 页面条件 | 预期结果 |
| --- | --- |
| 目标日期显示 `2026年8月17日` 或 `2026-08-17` | 日期证据匹配，继续识别页面 |
| 目标日期只显示 `8月1日`、`08-01`、`08/01` 或 `08.01` | 日期证据匹配，继续识别页面 |
| 显示 `8-1`、`8/1`、`8.1`、`评分8.1`、`版本8.1.0`、`￥8.01` 或 `8.01元` | 不作为日期证据，保持等待且不点击 |
| 非目标年份与目标月日位于同一节点、父子节点，或同一父节点下源索引相距不超过 2 | 保持等待，不点击，并记录日期不匹配 |
| 页面远端无关区域显示其他年份，目标月日本身正确 | 无关年份不阻止日期证据匹配 |
| 页面显示相邻日期 | 保持等待，不点击，并记录日期不匹配 |
| 页面未加载完成或证据不足 | 保持等待，不点击，并记录页面证据不足 |
| 悬浮“开始”刚被点击，活动根属于本助手，且大麦上方确有本助手无障碍浮层 | 允许忽略本助手浮层并采集底层大麦页面 |
| 活动根属于本助手，但大麦上方没有本助手无障碍浮层 | 拒绝回退，不生成目标快照 |
| 大麦上方存在系统、第三方、未知类别或其他应用窗口 | 采集和动作执行前校验均拒绝，不越过遮挡层操作底层大麦 |
| 活动根为空、属于系统或第三方 | 不生成目标快照，保持探测 |
| 连续 3 秒没有可读大麦窗口 | 显示确认大麦在前台的脱敏提示，并继续每 300ms 探测 |
| 快照后、动作执行前顶层大麦窗口 ID 变化 | 拒绝本次动作并安全暂停，不发生误点 |
| 任务运行中重绑无障碍服务，目标页面保持静止 | 重绑后无需刷新或额外页面事件，继续主动采集并恢复识别 |

### TC-P05：悬浮停止

操作：点击左上角悬浮控件中的“停止”。扩展服务生命周期回归时，对同一任务连续发送多个
停止请求，并在结束过程中发送一次开始、暂停或恢复控制 intent。

预期结果：

- 悬浮控件消失。
- 常驻运行通知消失。
- 停止后不再产生任何自动点击。
- 再次打开配置页后可以创建新任务。
- 重复停止和后续控制 intent 不会留下前台服务；紧接着创建的下一任务可以正常启动和停止。

### TC-P06：通知停止

操作：

1. 再次启动任务。
2. 下拉手机通知栏。
3. 点击购票辅助通知中的“停止”。

预期结果与 TC-P05 相同。

### TC-P07：悬浮区域触摸

操作：

1. 启动任务并手动打开一个普通手机页面。
2. 点击悬浮日志区域周围以及控制按钮外的页面区域。

预期结果：

- 日志窗口本身不获取输入焦点。
- 控制按钮外的触摸仍由下层页面接收。
- 只有悬浮“停止”按钮区域执行停止。

## 7. 大麦真机流程测试

测试顺序固定为：

1. 先在大麦完成目标和观演人配置。
2. 再在购票辅助选择演出日期并填写票档价格。
3. 点击“保存配置并显示悬浮窗”。
4. 由测试人员手动打开目标大麦页面。
5. 点击悬浮“开始”，观察日志、页面变化和动作结果。

### 7.1 只抢票

前置条件：

- 选择“只抢票”。
- 大麦中已经配置目标场次、票档、数量和实名观演人。
- 测试人员手动打开目标项目详情页。

验收点：

- “已预约”期间只等待，不产生点击。
- “立即预订”变为可见、启用且可点击后只点击一次。
- 进入购票入口页后，演出日期和票档价格一致才点击“去选座”。
- 确认页的演出日期、票档价格一致，且“立即提交”可点击时才提交。
- 弹窗同时存在“继续尝试”和“返回重新选购”时，只点击“继续尝试”。
- 弹窗只有“返回重新选购”时停止任务。

### 7.2 只抢回流

前置条件：

- 选择“只抢回流”。
- 测试人员先手动打开目标项目的场次和票档页面。
- 配置固定演出日期和票档价格。

验收点：

- 目标票档缺货时不选择其他票档。
- 不点击灰色不可用的“确定”。
- 返回项目详情页后只使用“立即预订”重新进入。
- 重新进入后不重复点击已经选中的日期。
- 目标票档恢复时，只选择配置中的固定票档。
- 票档、价格、数量一致并且“确定”可点击后才提交。
- 一次返回重新选购不会擅自改变固定目标。

### 7.3 抢票后接回流

前置条件与只抢票相同，运行模式选择“抢票后接回流”。

验收点：

- 首次开售流程按照 7.1 执行。
- 首次开售弹窗只能返回重新选购时，才切换至回流阶段。
- 切换后继续使用任务开始前保存的场次、票档、价格和数量。
- 回流阶段按照 7.2 执行。
- 受动作冷却和同页重试保护限制，不形成无间隔快速循环。

## 11. 安装和升级问题

### 11.1 设备显示 unauthorized

查看手机屏幕上的 USB 调试授权对话框，核对连接的电脑后允许本次连接，再次执行：

```bash
/tmp/ticket-assistant-sdk.w4lEPf/platform-tools/adb devices -l
```

### 11.2 APK 签名不一致

如果 ADB 明确报告签名不一致，说明手机上的旧版本与本次 APK 不是同一签名。

卸载会删除购票辅助的本地任务和运行日志。确认这些数据不需要保留后，才能执行：

```bash
/tmp/ticket-assistant-sdk.w4lEPf/platform-tools/adb uninstall \
com.ticketassistant.android
```

然后重新安装 APK，并重新开启无障碍和通知权限。

### 11.3 开始后没有悬浮控件

按以下可观察状态检查：

1. 配置页是否显示“无障碍服务 · 已开启”。
2. 配置页是否显示“运行通知 · 已开启”。
3. 通知栏是否存在“购票辅助正在运行”。
4. 是否有字段校验错误。
5. 是否已有另一个任务正在运行。

记录实际页面和通知状态，不根据未观察到的信息判断原因。

### 11.4 点击悬浮“开始”后一直显示“识别中”

1. 确认当前前台应用为大麦，并等待页面加载完成。
2. 查看悬浮日志中的等待原因，核对目标日期、票档价格和当前模式允许的起始页面。
3. 日期页面可以显示完整年月日或只显示月日；中文月日可以不补零，无年份数字月日必须使用
   双位 `MM-DD`、`MM/DD` 或 `MM.DD`，评分、版本号和价格文本不能当作日期。
4. 非目标年份只有在与月日属于同一日期结构时才阻止匹配；页面远端无关年份不影响正确月日。
5. 同类提示 15 秒内会被合并，长时间等待时允许低频再次出现。切换页面后观察等待原因是否
   变化，不要把日志未刷屏误判为停止轮询。
6. 仍无法识别时，停止任务并按第 10 节采集脱敏日志，同时记录页面截图和最短复现步骤。

## 13. 测试结束

1. 使用悬浮按钮或运行通知停止任务。
2. 确认悬浮控件和常驻通知消失。
3. 确认大麦中不存在本次测试不需要的待支付订单。
4. 关闭 USB 调试，或在开发者选项中撤销不再需要的调试授权。
5. 如果不再使用测试 APK，可以从系统应用设置中卸载“购票辅助”。

完成实体手机测试后，把手机型号、Android 版本、大麦版本和各测试用例结果补充到
`docs/验收记录.md`，才能形成对应真实设备和真实大麦版本的发布依据。
